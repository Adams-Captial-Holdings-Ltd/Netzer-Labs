### 3.3 Patterns and conventions to follow

- Pass `origin: baseUrl` on every Paperclip request from the bootstrap: `boardMutationGuard` refuses board mutations without it (`scripts/lib/paperclip/bootstrap-core.ts:115`).
- Diff secrets by field name and set/`REPLACE_ME` state only. The bootstrap `--dry-run` prints names; the deploy step prints "value not shown"; no handoff, log or PR ever carries a value.
- Compare failing test **file names** with their cause, never counts. Counts moved with every cut, and every recorded count in the 2026-09-01 file's section 7 was wrong (M50).
- Tests assert behaviour, not source text. `readFileSync` + `toContain` on a sibling file proves the text exists, nothing more. The marker pin in the image-pipeline test is the sanctioned exception: it pins a workflow string to an exported constant the workflow cannot import.
- A parameter every caller passes as one constant is dead code; delete it rather than testing it.
- An ECS secret entry must name a field that exists in the stored secret; a missing field fails the task at start with `ResourceInitializationError`, so `REPLACE_ME` is the safe placeholder, never absence. Who creates the fields, from the code: `infra/lib/secrets-stack.ts:113-118` creates the secret with `better_auth_secret`, `reconciler_key`, `agent_keys` and `dispatch_secret` — three bridge keys plus the auth secret; `company_id` is **not** in that list. It is merge-added as `REPLACE_ME` by deploy phase b's populate step (`scripts/lib/lifecycle/deploy-phases.ts:300-302`: `defaults: JSON.stringify({ company_id: 'REPLACE_ME' })`, `mergeExisting: true`, `writeIfAbsent: ['better_auth_secret']`), which is what the reworded comment at `infra/lib/compute-stack.ts:587-591` says. The older comment at `infra/lib/compute-stack.ts:236-244` claims `secrets-stack.ts` creates all four including `company_id`; it is wrong (P5, the code wins) and is not an authority — the source fix is deferred in section 6.4.
